### How we contain Claude across products

**环境层 containment 是 agent 安全的第一道防线，模型层行为引导是第二道，两者必须叠加。**

Anthropic 详细披露了三种 agent 隔离架构：claude.ai 用 ephemeral gVisor 容器（最小爆炸半径但无持久工作区），Claude Code 用 human-in-the-loop sandbox（Seatbelt/bubblewrap，权限提示减少 84%），Claude Cowork 用 sealed VM（完整 Linux 内核，凭据留在宿主 keychain 永不进入 guest）。文章坦陈三次重大安全失误：Claude Code 在信任对话框前就执行了项目配置中的 hook；内部红队成功钓鱼员工让 Claude 外泄 AWS 凭据（25 次尝试成功 24 次）；Cowork 的 egress allowlist 被绕过，攻击者通过 api.anthropic.com 的 Files API 将数据上传到自己的 Anthropic 账户。核心教训：自定义组件是最薄弱环节（hypervisor 和 seccomp 从未出事，自定义 proxy 出了事）；egress 控制应被视为 capability grant 而非 destination filter；用户能力决定 containment 策略，开发者能读 bash 但知识工作者不能。

### Scaling Managed Agents: Decoupling the brain from the hands

**将 agent 的 brain、hands、session 解耦为独立接口，是让 agent 可靠扩展的关键。**

受操作系统将硬件虚拟化为 process/file 等持久抽象的启发，Managed Agents 将 agent 虚拟化为 session（append-only 事件日志）、harness（调用 Claude 并路由 tool call 的循环）和 sandbox（代码执行环境），三者可独立替换和失败恢复。最初所有组件塞进一个容器（"pet"模式），容器挂了 session 就丢了，调试必须进容器但里面有用户数据。解耦后：harness 调用 sandbox 如同调用任何 tool（execute → string），sandbox 变成"cattle"可随时重建；session 日志在 harness 外持久存储，harness 崩溃后可用 wake(sessionId) 恢复；凭据通过 vault + proxy 机制永远不进入 sandbox。性能收益：p50 TTFT 降低约 60%，p95 降低超 90%。多 brain 多 hand 架构下，brain 可以将 hand 传递给其他 brain。

受 OS 虚拟化硬件启发，Managed Agents 将 agent 解耦为 session、harness、sandbox 三个独立接口。解耦后 sandbox 变 cattle 可随时重建，harness 崩溃可从 session 日志恢复，凭据永不进入 sandbox。p50 TTFT 降约 60%，p95 降超 90%。多 brain 多 hand 架构下 brain 可将 hand 传递给其他 brain。
