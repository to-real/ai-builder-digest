## Latent Space — [One Million AI Engineer Special] How Stanford Teaches AI-Native Engineering — Mihail Eric, Monaco

*Latent Space*

**The first AI-native engineer generation must operate near senior level from day one — the new bottleneck is code review, not code generation.**

Mihail Eric, Adjunct Professor at Stanford and Head of AI at Monaco, teaches CS 146S "The Modern Software Developer" — now in its second iteration, radically updated because autonomous coding agents went from emerging to dominant in one year. Every student in the class uses coding agents exclusively; not a single one types code by hand.

The 10-week curriculum moves from building a coding agent from scratch (~200 lines) through context engineering, skills, agent-ready codebases, agentic code review, security, background agents, to the software factory. The biggest shift from last year: from a broad survey of "where can you use agents" to solidifying principles around context engineering and architecture as the levers for complex tasks.

Eric's most provocative claim: "Most students are cooked, some of them are gonna be super valuable." The floor has risen dramatically — junior engineers must now perform near senior level because agents handle the implementation details. What remains valuable is foundational software engineering knowledge: understanding trade-offs, system design, and the ability to adjudicate between approaches.

The course replaces traditional assignments with open-source contributions to AI-native repos, so students get mentorship from maintainers and build mental models of production-grade software. Eric used MITMProxy to intercept Claude Code's actual requests, showing students the real system prompt, plan prompt, and compaction prompt live.

On tooling at Monaco, Eric follows "buy to learn and build to keep" — they converged on Devin for code review organically, but built their own background agent platform (Monocoder) and SRE bot (Hal) in-house when no mature offering existed. Code review is the new bottleneck: with agents generating 30+ PRs a day, the question is what class of changes can be auto-approved based on thoughtful agent-readiness design, and where humans must still insert themselves.

Mihail Eric 是斯坦福兼职教授兼 Monaco AI 负责人，教授 CS 146S"现代软件开发者"——现在已是第二轮，因自主 coding agent 从新兴到主导只用了一年而大幅更新。课上每个学生都只用 coding agent，没有一个人手写代码。

10 周课程从用约 200 行代码从零搭建 coding agent 开始，经过 context engineering、skills、agent-ready 代码库、agentic code review、安全、background agent，到 software factory。相比去年最大的转变：从"哪里能用 agent"的广泛调研，转向以 context engineering 和架构作为复杂任务的核心杠杆。

Eric 最具争议的判断："大多数学生完了，少数人会超级有价值。"门槛急剧抬高——初级工程师必须接近资深水平才能胜任，因为 agent 处理了实现细节。真正有价值的是基础软件工程知识：理解权衡、系统设计、以及在方案间做出裁决的能力。

课程用对 AI-native 开源项目的贡献替代传统作业，让学生从维护者那里获得指导并建立生产级软件的心智模型。Eric 用 MITMProxy 拦截 Claude Code 的实际请求，向学生展示真实的 system prompt、plan prompt 和 compaction prompt。

在 Monaco 的工具选型上，Eric 遵循"买来学习，留下自建"原则——代码审查自然收敛到 Devin，但 background agent 平台（Monocoder）和 SRE 机器人（Hal）因无成熟方案而自建。Code review 是新瓶颈：agent 每天能生成 30+ PR，核心问题是哪些变更可以基于 agent-readiness 设计自动批准，哪些必须人工介入。
