## Aaron Levie

*CEO, Box*

**Agent swarms turn bounded chat-rate productivity into unbounded parallel compute, and our brains aren't wired for that.**

We're shifting from AI that works at conversation speed to agents that fan out arbitrarily large work in parallel. This moves productivity gains from 20-50% to gains with no upper limit. Cyber, scientific fields, and life sciences are next after coding. Meanwhile, every 3-6 months you should re-check what's newly possible — models now have better tool use, less context rot, deeper domain expertise, and can leverage existing systems via APIs rather than generating everything from whole cloth. This creates autonomous collaborators for every job function.

我们正从对话速度的 AI 转向能并行展开任意规模工作的 agent swarm。生产力提升从 20-50% 跃升到没有上限。网络安全、科研和生命科学是编码之后的下一个战场。同时，每 3-6 个月都该重新测试新能力——模型现在 tool use 更强、context rot 更少、领域专长更深，还能通过 API 调用现有系统而非从零生成。这将为每个岗位创造自主协作者。

## Latent Space — [One Million AI Engineer Special] How Stanford Teaches AI-Native Engineering — Mihail Eric, Monaco

*Latent Space*

**The floor for new engineers has risen to near-senior level — "most students are cooked, some of them are gonna be super valuable."**

Mihail Eric, Adjunct Professor at Stanford and Head of AI at Monaco, teaches CS 146S: The Modern Software Developer. Now in its second iteration, the 10-week curriculum has shifted from a broad survey of coding agents to practitioner-focused training on what actually works at scale. Students build a coding agent from scratch in 200 lines, then reverse-engineer Claude Code's actual system prompt using MITMProxy. Assignments are no longer toy exercises — students contribute to real open-source AI-native repos (Factory, Cognition, OpenAI as partners), with maintainers reviewing their code. Every student surveyed uses coding agents; nobody types by hand anymore.

Context engineering at scale is the critical skill most practitioners never progress beyond vanilla prompting. For million-line codebases, you need structured research-proposal-plan workflows. Code review has become the new bottleneck as AI velocity outpaces human review capacity. Agent readiness — making repos verifiable and understandable by agents — is the prerequisite before multi-agent parallelization makes sense.

On tooling: "buy to learn and build to keep." Monaco evaluated every code review vendor, converged on Devin organically, but built their own background agent platform and SRE bot in-house. Even skills have a gardening problem: "there are very smart people at OpenAI and Anthropic that want skills to die. It just feels sloppy."

Mihail Eric 是 Stanford 兼职教授兼 Monaco AI 负责人，教授 CS 146S：现代软件开发者。课程进入第二轮，10 周内容从 coding agent 概览转向真正在大规模代码库中有效的实操训练。学生用 200 行代码从零构建 coding agent，再用 MITMProxy 逆向工程 Claude Code 的真实 system prompt。作业不再是玩具练习——学生向真实的 AI-native 开源项目贡献代码，由维护者审阅。调查中每个学生都在用 coding agent，没人手写代码了。

大规模 context engineering 是关键技能，多数从业者停留在 vanilla prompting。百万行代码库需要结构化的 research-proposal-plan 工作流。Code review 成为新瓶颈——AI 产出速度远超人类审阅能力。Agent readiness（让代码库对 agent 可验证、可理解）是多 agent 并行化的前提。

工具选择原则："buy to learn, build to keep"。Monaco 评估了所有 code review 供应商，有机地选择了 Devin，但自建了后台 agent 平台和 SRE 机器人。连 skills 都有养护问题："OpenAI 和 Anthropic 的聪明人想让 skills 死掉，因为太乱了。"
